# v2 설계 1 — 데이터 구조와 동기화

> 상태: 초안 (2026-10-15) · 브랜치 `v2`
> 범위: 새 앱(React + TypeScript + Tauri 2)이 **우리 서버 없이** 사용자 본인의 클라우드 폴더
> (OneDrive · Google Drive)로 여러 기기를 맞추는 방법. 화면 설계는 다음 문서.

## 1. 목표와 제약

| 목표 | 뜻 |
|---|---|
| **오프라인 우선** | 인터넷이 없어도 모든 기능이 됨. 동기화는 나중에 따라옴 |
| **본인 클라우드 (BYOC)** | 기록은 사용자 드라이브의 `DailyTodo/` 폴더에만. 우리 서버 · 회원가입 없음 |
| **여러 기기** | Windows · Mac · 휴대폰. 같은 시간에 다른 기기에서 고쳐도 **기록이 사라지지 않음** |
| **개인정보** | 우리가 아무것도 수집하지 않음. 원하면 비밀번호로 **종단 간 암호화** |
| **v1 에서 이어가기** | 지금 앱(v1)의 JSON 기록을 그대로 가져옴 |

받아들이는 한계: 동기화는 드라이브 속도에 따라 **몇 초~몇 분 지연**. 다른 사람과 공유하는 기능은 범위 밖.

## 2. 왜 v1 구조로는 안 되나

v1 은 `tasks.json` 같은 파일을 **통째로 덮어씀**. 두 기기가 거의 동시에 저장하면
드라이브는 한쪽을 이기게 하거나 `tasks-PC이름.json` 같은 충돌 사본을 만듦 → 한쪽 기록이 사라짐.
또 타이머가 `elapsed`(누적 초) 하나의 숫자라, 두 기기에서 잰 시간을 **합칠 방법이 없음**.

## 3. 핵심 아이디어

1. **기기마다 자기 파일에만 씀** — 각 기기는 `log/<기기ID>/` 아래 자기 변경 기록에 **덧붙이기만** 함.
   남의 파일은 읽기만 하므로 드라이브 충돌이 원천적으로 생기지 않음.
2. **항목 · 칸 단위로 합침** — 모든 기기의 변경 기록을 읽어서, 같은 항목의 같은 칸은
   **더 나중 시각(HLC)** 의 값이 이김. PC 에서 제목을, 휴대폰에서 완료 체크를 동시에 바꿔도 둘 다 남음.
3. **합칠 수 없는 값은 쌓는 값으로** — 타이머는 "누적 초"가 아니라 **측정 구간(세션)들의 모음**.
   세션은 기기마다 따로 생기니 합치면 그냥 합집합 → 충돌 없음.

## 4. 폴더 구조 (클라우드)

```
DailyTodo/                          ← 사용자가 고른 클라우드 폴더
  vault.json                        보관함 정보: 형식 버전, 보관함 ID, 암호화 여부(+ 키 확인용 값)
  devices/<deviceId>.json           기기 이름 · 종류 · 마지막 접속 (두 기기 동시 사용 안내에도 씀)
  log/<deviceId>/2026-10.ndjson     그 기기의 변경 기록, 한 줄 = 변경 하나, 달마다 새 파일
  snapshots/<deviceId>.json         (선택) 빠른 시작용 압축 상태 + 어느 기록까지 반영했는지
  blobs/<sha256>.<확장자>            사진 · 첨부 파일, 내용 해시가 이름 → 한 번 쓰면 안 바뀜
```

- 월별로 파일을 나누는 이유: 오래된 달 파일은 다시 안 바뀌므로 동기화 · 읽기가 가벼움.
- 휴대폰은 폴더 대신 드라이브 API 로 같은 구조를 읽고 씀 (8장).

## 5. 데이터 모델

### 5.1 모든 항목의 공통 칸

| 칸 | 설명 |
|---|---|
| `id` | UUIDv7 (시간 순으로 정렬되는 ID). 어느 기기에서 만들어도 겹치지 않음 |
| `type` | `task` · `session` · `event` · `deadline` · `goal` · `habit` · `habitCheck` · `mood` · `journal` · `moment` · `record` · `mandala` … |
| `createdAt` | 만든 시각 (HLC) |
| 각 칸의 `HLC` | 칸마다 마지막으로 바뀐 시각 — 합칠 때 씀 (저장은 변경 기록 쪽에) |
| `deleted` | 지움 표시 (실제로 지우지 않아야 다른 기기의 옛 값이 되살아나지 않음) |

### 5.2 종류별 (v1 과의 대응)

| 종류 | 주요 칸 | v1 |
|---|---|---|
| `task` | `day`(YYYY-MM-DD), `title`, `done`, `doneAt`, `parentId`, `order`, `note`, `estimateMin`, `collapsed`, `ref`(만다라트 · 기록장 연결) | `tasks.json` 의 항목 |
| `session` | `taskId`, `start`, `end`(진행 중이면 없음), `deviceId`, `kind`(normal · pomodoro · imported) | `elapsed` · `started_at` · `pomos` |
| `event` | `day`, `time`(없으면 미정), `title`, `remindMin` | `events.json` |
| `deadline` | `date`, `title`, `groupTitle` | `deadlines.json` |
| `goal` | `title`, `targetHours`, `linkedTitles[]` | `goals.json` |
| `habit` / `habitCheck` | `name` / `habitId` + `day` (체크 하나 = 항목 하나) | `habits.json` |
| `mood` | `day`, `level` | `moods.json` |
| `journal` | `day`, `text` | `journal.json` |
| `moment` | `at`(시각), `text`, `tags[]`, `blobIds[]`, `mood` | **새로**: 타임라인 일기 |
| `record` | `collection`(bucket · places · reviews · hobby · 사용자 정의), `title`, `tags[]`, `fields{}` | `collections.json` |
| `mandala` | `center`, `subs[8]`, `actions[8][8]`, `done[8][8]` (칸 단위로 쪼개서 저장) | `mandalart.json` |

- **순서(드래그 정렬)**: `order` 에 **분수 인덱스 문자열**(예: `"a0"`, `"a0V"`)을 씀.
  사이에 끼우면 두 값 사이 문자열을 새로 만들 뿐이라 다른 항목은 안 바뀜 → 기기 간 충돌 없음.
- **"완료하면 타이머 정지"** 같은 규칙은 저장된 값이 아니라 앱 로직이 세션을 닫는 것으로 표현.
- **설정**: 기기마다 다른 것(창 위치 · 단축키)은 그 기기 안에만, 모두 같은 것(테마 · 켜 둔 기능 · 습관 목록)은
  `type: "setting"` 항목으로 동기화.

### 5.3 타이머 = 세션

```
session { taskId, start: 1729000000000, end: 1729003600000, deviceId: "pc-1" }
지금까지 잰 시간 = 그 할 일 세션들의 (end ?? 지금) - start 합계
```
- 자정 분할 · 자리 비움 빼기 = 세션의 `end` 를 바꾸거나 세션을 둘로 나누기 → 기존 v1 기능을 그대로 표현.
- 두 기기에서 같은 할 일 타이머를 동시에 켜면 세션이 두 개 생김 → 앱이 "두 기기에서 재는 중" 을 알려 주고
  한쪽을 닫게 함 (데이터는 안 깨짐).

## 6. 변경 기록 (op log)

한 줄 = JSON 하나 (NDJSON):

```json
{"op":"set","id":"0192…","type":"task","f":{"title":"KAMP 제출","done":true},"t":"1729000000123:0004:pc-1"}
{"op":"del","id":"0192…","t":"1729000000456:0000:phone-1"}
```
- `t` 는 **하이브리드 논리 시계(HLC)**: `벽시계 ms : 같은 ms 안의 순번 : 기기ID`.
  기기 시계가 조금 틀려도 순서가 뒤집히지 않고, 같은 시각이면 기기ID로 결정 → **모든 기기가 같은 결과**.
- 합치는 규칙: 같은 `id` 의 같은 칸은 `t` 가 큰 값. `del` 은 그보다 늦은 `set` 이 없으면 지운 것.
- 같은 일기(`journal.text`)를 두 기기에서 동시에 길게 고친 경우만은 한쪽이 묻힐 수 있음 →
  덮인 쪽을 **"다른 기기에서 쓴 내용"** 으로 보관하고 화면에서 알려 줌 (자동으로 버리지 않음).

## 7. 동기화 흐름

```
[이 기기 화면] ─변경→ [로컬 DB (SQLite)] ─모아서 덧붙이기→ log/<내 기기>/YYYY-MM.ndjson
                          ↑ 합치기
   log/<다른 기기들>/*.ndjson ← 드라이브가 내려받음 (PC) / API 로 내려받음 (휴대폰)
```
1. **쓰기**: 변경 → 로컬 DB 에 바로 반영 (화면은 즉시) → 1초 정도 모아서 내 기록 파일에 덧붙임.
2. **읽기**: 시작할 때 · 1분마다 · 폴더 변경 알림이 오면, 다른 기기 기록 파일의 **읽은 위치 이후만** 읽어서 합침.
   기기별 "어디까지 읽었나"(파일 · 줄)는 로컬에 저장.
3. **정리(압축)**: 기록이 많이 쌓이면 이 기기가 아는 전체 상태를 `snapshots/` 에 저장.
   새 기기는 스냅샷 + 그 이후 기록만 읽으면 됨. 오래된 기록 파일은 모든 기기가 반영한 뒤 보관 폴더로.
4. **두 기기 동시 사용**: 이제 데이터가 깨지지 않으므로 v1 의 "동시 사용 경고"는 안내 정도로만.

## 8. 기기별 연결 방법

| 기기 | 방법 | 로그인 |
|---|---|---|
| Windows · Mac | 동기화 앱(OneDrive · Google Drive)이 만든 **폴더를 그대로** 읽고 씀 | 없음 |
| 휴대폰 | **드라이브 API** (Microsoft Graph · Google Drive API) 로 같은 폴더 구조를 읽고 씀 | "Microsoft/Google 로 로그인" 한 번 (OAuth) |

- 휴대폰은 **앱 전용 폴더 권한**만 요청 (OneDrive `App folder` · Google Drive `drive.file`/`appDataFolder`)
  → 사용자 다른 파일은 못 봄, 구글 · MS 앱 심사도 가벼움.
- 그런데 앱 전용 폴더는 PC 동기화 폴더에서 위치가 정해져 있음 (예: OneDrive `앱/DailyTodo`) →
  **PC 도 그 위치를 기본값으로** 써서 같은 폴더를 보게 함.
- 변경 감지: Graph `delta` · Drive `changes` API 로 바뀐 파일만 받기.
- iCloud 는 1단계 범위 밖 (iPhone 사용자도 OneDrive/Google Drive 로 연결).

## 9. 암호화 (선택)

- 보관함 만들 때 "비밀번호로 잠그기" 선택 → Argon2id 로 키를 만들고, 기록 한 줄 · 첨부 파일마다
  XChaCha20-Poly1305 로 암호화. `vault.json` 에는 소금값과 키 확인값만.
- 드라이브 업체도 내용을 못 읽음. **비밀번호를 잊으면 복구 불가** → 복구 키를 한 번 보여 주고 적어 두게 함.
- 나중에 켜고 끌 수 있도록 형식에 처음부터 자리를 만들어 둠.

## 10. v1 에서 옮기기

- 새 앱 처음 실행 → "v1 기록 가져오기"로 `%APPDATA%\DailyTodo\location.json` 이 가리키는 폴더(지금은 OneDrive)를 찾음.
- v1 JSON 을 읽어 `import` 기기 이름으로 변경 기록을 만듦:
  - `elapsed` → 그날 끝에 끝나는 `session`(kind: imported) 하나, 진행 중 타이머는 열린 세션
  - 묶음 · 순서는 `parentId` · `order` 로, 기록장 · 만다라트 · 일정 · 마감 · 습관 · 기분 · 일기 모두 대응
- v1 파일은 **건드리지 않음** → 옮기는 동안 v1 앱을 계속 써도 되고, 다시 가져오기로 맞출 수 있음.
- 가져온 뒤 개수 · 총 시간 비교표를 보여 주고 사용자가 확인.

## 13. 정한 것 (2026-10-15)

### 휴대폰 첫 버전 범위
- **할 일**: 날짜별 목록 보기, 완료 체크 (묶음 펼치기 포함). 간단한 추가까지.
- **일정 · 마감**: 보기 + 추가 · 수정 · 삭제 (일정표처럼 주/달 보기, 디데이).
- **데이트 일기**: 쓰기 · 보기 (장소 · 별점 · 쓴 돈 · 사진 · 이야기). 데이트 중에 휴대폰으로 사진과 함께 바로 남기는 용도.
- 타이머 · 기분 · 습관 · 다른 기록장 · 통계는 **PC 에서만** → 휴대폰은 다음 버전부터.
  (데이터는 다 동기화되므로 휴대폰 화면만 나중에 더하면 됨)

### 사진 첨부: 줄여서 저장
- 긴 변 **2048px**, **WebP 품질 80** 으로 변환해 `blobs/` 에 저장 (대략 원본의 1/5~1/10).
  목록용 **썸네일 400px** 을 따로 만들어 둠.
- 위치(GPS) 같은 **EXIF 정보는 지움** (개인정보), 촬영 시각만 남김.
- 원본은 저장하지 않음 (필요하면 나중에 "원본 보관" 옵션).

### 기록장: 처음엔 다이어리 + 데이트 일기
- v2 첫 버전의 기록장 = **다이어리** (하루 한 편 글 + 타임라인 일기, 기분, 그날 요약, 사진)
  + **데이트 일기** (`record`, collection = `date`: 날짜 · 장소 · 별점 · 쓴 돈 · 사진 여러 장 · 이야기 · 태그).
  v1.1.0 에 먼저 들어가 있음 — v1 은 사진 한 장, v2 는 여러 장.
- 버킷리스트 · 가고 싶은 곳 · 콘텐츠 리뷰 · 취미 · 사용자 정의 모음은 **나중에 확장**.
- 단, v1 의 해당 기록도 **가져오기 때는 `record` 항목으로 모두 옮겨 둠** → 화면이 생기면 바로 보임, 기록은 안 잃음.

### v2 데이터 폴더
- v2 는 OneDrive **앱 전용 폴더**(`OneDrive\앱\DailyTodo`)를 씀 — 휴대폰이 그 폴더 권한만 받으면 되도록.
  Google Drive 는 `appDataFolder` 대신 사용자가 볼 수 있는 `drive.file` 폴더 (내보내기 · 백업 확인이 쉬움).
- v1 이 쓰는 `OneDrive\DailyTodo` 는 **가져오기 원본으로 읽기만** 함 (v1 을 쓰는 동안 둘이 섞이지 않음).

### 공유 없음
- 데이트 일기를 포함해 모든 기록은 **혼자 쓰는 것**으로 확정 → 보관함은 한 사람 · 한 클라우드 계정.
  다른 사람과 같은 폴더를 쓰는 기능은 만들지 않음.
